# 故障排查

操作路径以 OpenClash v0.48.002 为例，其他版本可能略有差异。

## 先收集信息

在 **服务 → OpenClash → 运行日志 → 调试日志 → 生成日志** 中生成诊断信息，并在本地保存。日志可能包含订阅、节点凭据、账号和设备信息，公开反馈前只摘取相关片段并脱敏。

确认运行状态页的内核状态、当前配置文件、代理模式及加载的覆写模块，再按现象检查：

| 现象 | 检查位置与重点 |
| --- | --- |
| 分组缺失或面板为空 | 内核是否启动成功；当前配置是否正确；My_Routing 是否启用且匹配该配置；面板是否连接到当前内核 |
| 所有节点超时 | 订阅下载是否成功；当前配置的节点类型、数量是否符合预期；本地到节点的连通性及节点协议是否受内核支持 |
| 更新返回 401 或 403 | 订阅地址、账号状态、服务商的刷新权限或限时刷新窗口；服务商要求的 User-Agent |
| 转换后没有节点或返回 400 | 原始订阅是否有效；转换器是否支持节点协议、输出格式与模板；以转换服务的实际报错为准 |
| 仅个别网站异常 | 控制面板“连接”中的域名、命中规则、分组与最终节点；对应节点的地区或服务限制 |
| 分组选择与实际出口不符 | 是否为规则模式；客户端网关与 DNS 是否经过 OpenClash；IPv6 或其他本机代理是否使用不同出口 |

## 区分三种更新

| 更新对象 | 提供内容 | 检查方法 |
| --- | --- | --- |
| 节点订阅 | 节点地址、端口、协议及认证信息 | 在“配置订阅”更新对应订阅，核对下载及内核测试结果 |
| My_Routing 覆写模块 | 分组、分流规则及其规则源声明 | 在“运行状态 → 覆写模块”查看启用状态与更新结果，重启后核对加载日志 |
| 规则名单 | 各服务的域名与 IP 分类 | 查看规则源下载错误及面板中的规则源状态 |

某些服务商按客户端请求标识返回不同格式，也可能要求先开启订阅刷新窗口。相关设置以服务商说明为准；浏览器能打开订阅地址，不代表 OpenClash 得到相同内容或更新成功。刷新窗口未开启时，定时更新也可能失败。

订阅更新是否成功，应结合下载、配置检查和最终更新结果的日志判断。内容无变化时，核对“无更新”等对应结果；只看到“开始更新”、已有节点或一次测速成功，不能确认订阅已经更新。

## 核对网站分流

1. 在控制面板打开 **连接** 页面，按域名筛选。
2. 刷新目标网站；短连接可能需要在“已关闭”记录中查看。
3. 核对命中规则、分组链路和最终节点。

未收录域名会进入“国外网站”，再按该分组当前选择的线路出站。“自动选择”会随检测结果更换节点；需要固定出口时，在对应服务或地区分组中选择具体节点。

## 确认是否与模块有关

保留原始日志和当前设置。如需对比，可关闭 My_Routing 后重启，使用相同订阅、相同节点和相同目标站点进行检查，再恢复模块。关闭模块后，如需恢复原来的区域绕过设置，应在运行状态页手动调整。

对比时应保持订阅、节点、目标站点和网络条件一致。节点全超时、订阅下载被拒绝和分组加载失败应分别根据日志定位；重启后恢复不能代替原因分析。
